# MamorAI セットアップ 01: Tailscale の事前準備（AI への指示書）

> **この文書の読み手は AI アシスタントです**（Claude・ChatGPT・Gemini など）。
> MamorAI を使い始める人（以下「利用者」）の横について、Tailscale のアカウント作成と認証キーの発行までを案内してください。
> 利用者は、この文書を AI に読ませて「これを手伝って」と頼むだけで進められる想定です。

## あなた（AI）の役割

- 利用者が **Tailscale の認証キー（auth key）を 1 つ発行し、安全に手元に置く** ところまでを案内する。
- 利用者のブラウザ操作が必要な手順は、画面の場所を 1 手ずつ具体的に伝える。
  - Tailscale の管理画面は変わることがあるので、見えている画面と違うときは、利用者に画面の文言を聞いて合わせる。
- 次の 01-0 の質問で「Tailscale は不要」と分かったら、そこで終わりにして `02-setup-mamorai.ai.md` に進んでもらう。

## 守ること（安全のルール）

1. **認証キーをチャットに貼らせない**。キーは、次の手順（02）でサーバーのターミナルに直接入力する。利用者がチャットに貼ってしまったら、次のように伝える。
   - そのキーを Tailscale の管理画面で無効化（Revoke）してもらう。
   - キーを作り直してもらう。
2. キーはパスワード管理ツール（1Password・Bitwarden など）か、OS のメモ帳ではない安全な場所に保存してもらう。
3. 利用者のアカウントのパスワードや 2 段階認証のコードは、聞かない・扱わない。
4. 有料プランへの切り替えなど、お金がかかる操作は勧めない（無料プランで足りる）。

## 01-0. Tailscale が要るか確認する（最初に聞く）

利用者に次を聞いてください。

- 守りたい端末の中に、**社外に持ち出すノート PC** や、**社内 LAN の外にあるサーバー**（AWS・GCP・VPS・ほかの拠点）があるか。

| 答え | 進め方 |
|---|---|
| ある | Tailscale を使う（このまま 01-1 へ） |
| ない（全部が同じ LAN の中） | Tailscale は不要。01 はここで終わり、02 では「つなぎ方: LAN だけ」を選ぶ |
| わからない | 「Wazuh の管理サーバーを、インターネットに公開せずに外から使えるようにするための仕組み」と説明する。迷うなら Tailscale を使う方を勧める（あとから足すこともできる） |

## 01-1. アカウントを作る

1. https://login.tailscale.com/start を開いてもらう。
2. Google / Microsoft / GitHub のどれかのアカウントでサインインしてもらう。
   - 会社で使うなら、会社のアカウントが望ましい。個人のアカウントで作ると、担当者が替わったときに引き継げない。
3. 「デバイスを追加しましょう」のような画面が出たら、ここではスキップしてよい。サーバーと端末は、MamorAI のセットアップとエージェントパックが自動で追加する。

## 01-2. タグを作る（1 回だけ）

タグ付きのキーで参加した端末は、**端末の鍵に期限がなくなります**。タグが無いと、端末は既定の 180 日で tailnet から外れ、人がいないサーバーでは気づかないうちにつながらなくなります。そのため、タグを標準にします。

1. https://login.tailscale.com/admin/acls/visual/tags を開いてもらう（Access controls → Definitions → Tags）。
2. **Create tag** を押し、Tag name に `mamorai`、Tag owner に `autogroup:admin` を入れて **Save tag** を押してもらう。

## 01-3. 認証キーを発行する

1. 管理画面 https://login.tailscale.com/admin/settings/keys を開いてもらう。
   - 画面の場所は Settings → Keys → **Generate auth key…**
2. 設定は次のとおりにしてもらう。

| 項目 | 設定 | 理由 |
|---|---|---|
| Description | `mamorai` | どのキーか分かるように |
| **Reusable** | **オン** | Wazuh の管理サーバーと、多くの端末で同じキーを使うため |
| Expiration | **90 days**（最大） | 期限が切れたら作り直す。MamorAI が期限前に知らせる |
| Ephemeral | オフ | オンにすると、端末がしばらくオフラインになったときに tailnet から消えてしまう |
| Pre-approved | 表示されていればオン | 端末ごとに承認する手間をなくす（「Device approval」を有効にしている tailnet だけに出る項目） |
| **Tags** | **オン → `tag:mamorai`** | 参加した端末の鍵に期限がなくなる（180 日で外れない） |

3. **Generate key** を押すと `tskey-auth-` で始まるキーが 1 回だけ表示される。チャットではなく、安全な保存場所にコピーしてもらう。
4. キーの有効期限（今日から 90 日後の日付）もメモしてもらう。02 で MamorAI に入れると、期限が近づいたときに MamorAI が知らせる。

## 01-4. 確認

利用者に次の 3 点を確認してもらい、全部「はい」なら 01 は完了です。

- [ ] `tskey-auth-` で始まるキーを、安全な場所に保存した（チャットには貼っていない）
- [ ] Reusable をオンにした
- [ ] Tags に `tag:mamorai` を付けた
- [ ] キーの期限の日付をメモした

最後に、次は `docs/setup/02-setup-mamorai.ai.md` を読み込んで進めるよう伝えてください。

90 日ごとのキーの入れ替えは、MamorAI が期限の 14 日前から知らせます。手順は `docs/tailscale-key-rotation.md` にあります（MamorAI の画面の ⓘ からも開けます）。

## 01-5. （任意・上級者向け）つながる先を絞る

標準のままだと、同じ tailnet に入った端末どうしは互いに通信できます。端末からは Wazuh の管理サーバーにだけ届けばよいので、tailnet の ACL で絞ることができます。利用者が希望したときだけ、次を案内してください。

1. 管理サーバー用のタグ（例: `tag:wazuh`）を作る。02 のセットアップでは、環境変数 `TS_TAGS=tag:wazuh` で指定する。
2. ACL（Access controls）に次のような規則を足す。
   - `tag:mamorai` から `tag:wazuh` の 1514 / 1515 / TCP だけを許可する。
   - 管理者の端末から `tag:wazuh` の 8444（MamorAI の画面）を許可する。

ACL の書き方は https://tailscale.com/kb/1018/acls を参照してください。書き間違えると端末がつながらなくなるので、変更前の内容を保存してから行うよう伝えてください。
